# Button

Buttons allow users to take actions and make choices with a single tap. Use buttons to communicate actions users can take throughout the UI in dialogs, forms, cards, and toolbars.

A live Flutter build of the button, rendered with `AsmButton` from `pegasus_flutter`. Each preview below is a live Flutter demo; switch the code tab to **Web** to see the web component equivalent.

<FlutterView height={520} />

## Usage

Use a button whenever the user needs to trigger an action or make a choice — submit a form, confirm a dialog, apply a filter. To navigate to a new URL, use a link instead of a button.

## Anatomy

```
┌───────────────────────────────────┐
│   [start-icon]   Label   [end-icon]    │
└───────────────────────────────────┘
        ↑            ↑           ↑
    Optional     Required     Optional
```

| Part | Description | Required |
|------|-------------|----------|
| Container | Background, border and radius resolved from the `variant`; padding resolved from the `size` | Yes |
| Label | The `label` text, rendered semibold | Yes |
| Leading icon | Material Symbols glyph set via `start-icon` (web) / `startIcon` (Flutter) | No |
| Trailing icon | Material Symbols glyph set via `end-icon` (web) / `endIcon` (Flutter) | No |
| State layer | Hover / pressed overlay tinted per variant | On interaction |
| Focus ring | 2px outline shown on `:focus-visible` | On focus |

## Behavior & States

Every variant responds to the same interaction states. Disabled buttons are removed from the tab order and suppress all pointer and keyboard activation.

| Variant | Default | Hover | Pressed | Focus | Disabled |
|---------|---------|-------|---------|-------|----------|
| `filled` | Primary background, on-primary label | + hover overlay | + pressed overlay | Focus ring | Reduced opacity, no pointer events |
| `tonal` | Surface-container background | + hover overlay | + pressed overlay | Focus ring | Reduced opacity, no pointer events |
| `text` | Transparent, primary label | Subtle overlay | Stronger overlay | Focus ring | Reduced opacity, no pointer events |
| `outline` | Transparent, 1px outline | + hover overlay | + pressed overlay | Focus ring | Reduced opacity, no pointer events |

Adding `destructive` swaps the color role to the error palette while keeping the same state behavior.

### Keyboard

| Key | Action |
|-----|--------|
| Enter | Activate the button |
| Space | Activate the button |
| Tab | Move focus to the next focusable element |
| Shift + Tab | Move focus to the previous focusable element |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Accessible name | `label` (web) — or `semanticLabel` on Flutter to override the spoken name |
| Element | Native `button` semantics on both platforms — never a `div` with a click handler |
| Keyboard | Enter and Space activate the button |
| Focus | Visible focus ring via `:focus-visible` |
| Disabled | `disabled` (web) / `onPressed: null` (Flutter) removes the button from the tab order |
| Touch target | Minimum 44×44px hit area |
| Icon-only usage | Provide `semanticLabel` / `aria-label` and a `tooltip` describing the action |
| Destructive | Pair with a confirmation step for irreversible actions |

## Guidelines

- Use clear, concise labels that describe the action
- Place the primary action button on the right in dialogs
- Avoid using too many buttons in one view
- Use filled buttons sparingly to emphasize the most important action
- Use the destructive option only for irreversible actions like delete

### Choosing a variant

```
Need a clickable action?
├─ Navigates to a URL?          → use a link, not a button
├─ Main / primary action?       → variant: filled (max one per view)
├─ Secondary action beside it?  → variant: tonal or outline
├─ Low-emphasis / inline?       → variant: text
└─ Destructive?                 → add destructive (+ confirm if irreversible)

Choosing a size
├─ Dense context (table, toolbar)? → size: compact
├─ Hero / marketing CTA?           → size: spacious or huge
└─ Otherwise                       → size: default
```

### Anti-patterns

- **Don't** place two `filled` buttons side by side — pair `filled` with `tonal` or `outline`.
- **Don't** ship a button with no accessible name — always supply `label` (or `semanticLabel` for icon-only).
- **Don't** run a destructive action without confirmation when it can't be undone.
- **Don't** invent variants — only `filled`, `tonal`, `text`, and `outline` exist on the web component.
- **Don't** build a button from a `div` — use `asm-button` / `AsmButton` for correct semantics.

## API

### Web

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `label` | `string` | `''` | The button label text |
| `variant` | `filled` \| `tonal` \| `text` \| `outline` | `filled` | The visual style |
| `size` | `huge` \| `spacious` \| `default` \| `compact` | `default` | The button size |
| `disabled` | `boolean` | `false` | Whether the button is disabled |
| `destructive` | `boolean` | `false` | Destructive/danger mode |
| `start-icon` | `string` | `''` | Material Symbols icon name before label |
| `end-icon` | `string` | `''` | Material Symbols icon name after label |

### Flutter

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `label` | `String` | required | The button label text |
| `automationIdentifier` | `String` | required | Stable id used for test automation |
| `onPressed` | `VoidCallback?` | `null` | Tap handler. `null` disables the button |
| `startIcon` | `Widget?` | `null` | Leading icon widget |
| `endIcon` | `Widget?` | `null` | Trailing icon widget |
| `variant` | `AsmButtonVariant` | `.text` | The visual style (`filled`, `tonal`, `text`, `textNoPadding`, `ghost`, `outline`, `strictBlack`, `strictWhite`) |
| `size` | `AsmButtonSize` | `.large` | The button size (`large`, `medium`, `small`, `xsmall`) |
| `destructive` | `bool` | `false` | Destructive/danger mode |
| `semanticLabel` | `String?` | `null` | Overrides the accessible label |
| `tooltip` | `String?` | `null` | Optional tooltip text |

## Contract

Machine-readable contract for AI agents and the component registry. This mirrors the real `asm-button` / `AsmButton` surface documented above — keep it in sync when the API changes.

```yaml
name: button
web_tag: asm-button
flutter_widget: AsmButton
type: interactive
category: action

props:
  label:
    type: string
    required: true
  variant:
    type: enum
    web_values: [filled, tonal, text, outline]
    flutter_values: [filled, tonal, text, textNoPadding, ghost, outline, strictBlack, strictWhite]
    web_default: filled
    flutter_default: text
  size:
    type: enum
    web_values: [huge, spacious, default, compact]
    flutter_values: [large, medium, small, xsmall]
    web_default: default
    flutter_default: large
  disabled:
    type: boolean
    default: false
    note: "Web only. On Flutter, pass onPressed: null to disable."
  destructive:
    type: boolean
    default: false
  start_icon:
    type: icon
    web_attr: start-icon
    flutter_prop: startIcon
    required: false
  end_icon:
    type: icon
    web_attr: end-icon
    flutter_prop: endIcon
    required: false
  automationIdentifier:
    type: string
    required: true
    platform: flutter
  semanticLabel:
    type: string
    required: false
    platform: flutter
  tooltip:
    type: string
    required: false
    platform: flutter

events:
  click: fired on activation (click, Enter, or Space)

constraints:
  - MUST have a visible label OR an accessible name (semanticLabel / aria-label)
  - Flutter AsmButton requires BOTH label AND automationIdentifier
  - Maximum ONE filled button per viewport
  - Destructive actions SHOULD trigger confirmation when irreversible
  - MUST NOT nest interactive elements inside a button
```
